# Ego Range Implementation Plan

**Goal:** Show a range ring around the ego, dim lidar points beyond it, and show each cuboid's
flat distance from the ego. Works in any reference frame.

**Spec:** `.experimental/superpowers/specs/2026-11-26-ego-range-design.md`

## Review focus

1. Reference frame equals ego frame: `[0, 0, 0]` without a transform lookup.
2. Ego frame not connected at a tick: `position` is `None`, HTTP 200, UI notice.
3. Point clouds in sensor frames: no ring, no dimming, notice.
4. Stored ego frame not in this sequence: ignored, default applies.
5. Corrupt local storage values: sanitized and clamped.

## Tasks

1. **Backend service and view**: `TickEgoPositionView`, `EgoPositionFrames`,
   `recording_service.get_tick_ego_position`. Tests: connected, same frame, transform not
   found, no timestamp, tick not found.
2. **Backend route**: `get_tick_ego_position` route, 404 on a missing tick, 422 on missing
   frames. Regenerate `openapi.json` and the frontend client.
3. **Frontend helpers**: `egoRange.ts` (distance, format), `egoRangeSettings.ts` (defaults,
   sanitizer, `resolveEgoFrame`).
4. **Hook and wiring**: `useEgoPosition`, `useEgoRange`, `getUnavailableReason`,
   `resolveEgoPosition`, `keepPositionForSameFrames`; expose `egoRange` on the workspace
   controller and layout context.
5. **Scene**: range dimming in `getPointCloudFrameColors`, `EgoRangeRing`, `EgoDistanceLine`,
   `EgoRangeSettings`, viewport notice.
6. **Annotation list**: `AnnotationEgoDistance` in the expanded row.
7. **Manual check** on an MCAP dataset: ring follows the ego in `map`/`odom`, radius change
   updates ring, dimming, and markers; no `ego-position` requests while off.
